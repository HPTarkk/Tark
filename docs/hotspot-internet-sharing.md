# Hotspot: internet sharing vs. local-only

Investigated 2026-11-12 for the question "can the host choose whether its
hotspot also shares internet?". Short answer: **no app can make that choice
on either platform**, so Tarkk does not offer a control for it. The invite
sheet instead says plainly what the hotspot is: a private link between the
phones that does not share internet.

## What Tarkk raises today

`HotspotHandler.kt` calls `WifiManager.startLocalOnlyHotspot` (API 26+). The
joining phone asks for that network with `WifiNetworkSpecifier` (API 29+;
`WifiJoinHandler.kt`) or `NEHotspotConfiguration` on iOS
(`HotspotJoinHandler.swift`).

## Android

| Capability | Third-party app? | Notes |
| --- | --- | --- |
| Local-only hotspot (`startLocalOnlyHotspot`) | Yes, API 26+ | By design it has **no upstream**: the framework never NATs it to mobile data or Wi-Fi. The system picks the SSID and passphrase. |
| Local-only hotspot with own SSID/passphrase (`startLocalOnlyHotspotWithConfiguration`) | Yes, API 36+ | Public since Android 16. Still local-only: it changes the name and band, not whether internet is shared. |
| Tethering hotspot, i.e. internet sharing (`TetheringManager.startTethering`) | **No** | Needs `TETHER_PRIVILEGED` (signature/privileged). API 36 made a subset public only for device-owner and carrier-privileged apps. The pre-Android 8 reflection route (`setWifiApEnabled`) is gone. |
| Reading the system hotspot's SSID/passphrase | **No** | `getSoftApConfiguration` is a system API, so a code for the system hotspot cannot be generated by Tarkk. |
| Opening the system hotspot screen | Yes | No public intent action; `com.android.settings.TetherSettings` works on most builds (`openTetherSettings`). The user must flip the switch. |
| Switching a running hotspot between the two modes | **No** | They are different soft-AP modes owned by different callers. A running system hotspot makes `startLocalOnlyHotspot` fail with `ERROR_INCOMPATIBLE_MODE` (surfaced in Tarkk as `tethering_on`). |

The joining side matters just as much. A network joined through
`WifiNetworkSpecifier` is given to the requesting app only: Android does not
make it the phone's default network, so even if the host *were* sharing
internet, the joiner's other apps would not get it. That is also why joining
Tarkk's hotspot does not cost either phone its own mobile data.

Version differences that affect Tarkk:

- Android 8–9: local-only hotspot available; the joiner uses the legacy
  join path.
- Android 10+: `WifiNetworkSpecifier` join, one system "Connect" prompt.
- Android 12 (observed in field logs): a hotspot cannot be raised while the app is in the background.
- Android 13+: `NEARBY_WIFI_DEVICES` replaces location for these calls.
- Android 16+: own SSID/passphrase for a local-only hotspot becomes possible.

## iOS

- There is no API to start, stop or configure Personal Hotspot, and none to
  create any other access point. Apple DTS: "No APIs exist that will allow
  an app to turn the iOS device into a hotspot."
- Personal Hotspot is always an internet-sharing hotspot and exists only
  while the phone has a cellular data plan that allows it. There is no
  local-only variant.
- An app can *join* a known network with `NEHotspotConfiguration` (needs the
  Hotspot Configuration entitlement), which Tarkk already does.
- So an iPhone can join a Tarkk hotspot but cannot host one for a code.

## What this means for the product

- The method on an invite is Hotspot (local-only, raised by Tarkk) or
  Bluetooth. Neither needs or provides internet, which matches the app's
  purpose: talking phone to phone with no coverage.
- No "share internet" switch is shown, because it would be a control the
  operating system does not let Tarkk honour.
- Each phone keeps its own mobile data while on a Tarkk hotspot. The host
  loses its own Wi-Fi internet on single-radio phones while hosting.

## Closest practical alternative

If one rider really wants to give the other internet, the only route is the
system's own hotspot, switched on by hand:

1. The host turns on the system hotspot in Settings (Tarkk can open the
   screen, not flip the switch).
2. The other phone joins it in its own Wi-Fi settings (Android shows a QR
   for this on the hotspot screen).
3. Both phones are then on one network and Tarkk talks over it as it does
   over any shared Wi-Fi.

Costs: two trips to Settings, the host's mobile data is used by the other
phone, and Tarkk cannot repair that hotspot when it drops, which is the thing
a rider cannot do mid-ride. It is therefore not built into the invite; it
stays a manual fallback rather than a promise in the UI.
